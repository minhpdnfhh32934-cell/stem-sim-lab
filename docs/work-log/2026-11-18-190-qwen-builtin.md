## Key decisions

- `builtin_ai_chat` is its own command (the local route's request, Rust fills in address, alias,
  key) instead of a flag on `local_ai_chat`: the page cannot send an address. Laptop agreed.
- `--port 0`, port read from the server's log (automated security review: a port picked in Rust
  and bound later could be taken by another program, which would get the key).
- Key through `--api-key-file`, deleted once ready (never on a command line).
- No `stemsim.builtin-ai` storage: Rust keeps the model and the fault switch.
- No version bump and no `versions.json` entry (laptop instruction; the release-notes test needs
  the first entry to equal `package.json`, so the entry comes with the user's version number).
- The Settings page keeps its name "Gemma cục bộ" (existing i18n lines not edited); rename in a
  separate PR after #190 (laptop).

`local::chat_cancellable` with the OpenAI-compatible body, which sends no thinking switch (`think`
is Ollama only), so Qwen 3.5 reasons first and llama.cpp puts all of that in `reasoning_content`,
which SimLab drops. Same server flags as `server.rs`, `Vulkan0`, the app's prompt from the 18/11
results file, the same question, `max_tokens` 2048 (`DEFAULT_MAX_TOKENS`):

- as the app sends it: 20,5 s, `finish_reason: "length"`, 0 characters of answer, 7 853 of reasoning;
- with `chat_template_kwargs: {"enable_thinking": false}` (what `eval-local.mjs` sent on 18/11):
  1,4 s, first piece 87 ms, `stop`, a correct Vietnamese answer.

So the 18/11 measurement (34/42) is valid only with thinking off, and the app does not turn it
off yet. Possible fix, waiting for the user's go-ahead (this check was told to change nothing else
in the PR): add `--chat-template-kwargs {"enable_thinking":false}` to the server's arguments in
`server.rs` (it then applies to every request, as in the measurement), with its test, then click
through this check again. Not looked into: why the app stops after 11–14 s instead of 20 s.
