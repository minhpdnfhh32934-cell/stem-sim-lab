## Key decisions

- The TikTok links in the brief were not opened or watched (not possible here); only the brief's
  own description (select a structure to read its information) was used as an idea.
- Model reused as is: the Interact step mounts the lab's `MitosisStage` (3D with tap-to-pick, 2D
  fallback without WebGL / Low quality) and `Mitosis3DParts`; `PartInfo` with "Hỏi thầy về bộ
  phận này" is untouched. Opening the step sets the division store to the lesson's cell
  (2n = 4, animal, 3D view).
- Prediction: "in which stage do double chromosomes line up in one row at the equatorial
  plane?" Choices are the model's 7 stage names. The answer is computed: at each stage's key
  moment the app counts chromosomes (centromeres), double chromosomes and centromeres on the
  plane x = 0 (tolerance 1e-6 for rounding only); exactly one stage must satisfy it, else the
  lesson shows a binding error. Recording a stage stores those counts as engine evidence; only
  the computed stage sets the verdict (same rule as the chemistry target mix).
- Activity: each task shows a part's function text from `COMPONENTS`; the learner answers with
  the part selected in the model. Right = the selected part is the function's own part. A
  checked sheet is stored as an engine record (facts only, no score number); changing an answer
  drops the check. The sheet is kept in the session action log, so it survives reopening.
- Generic extension: `completion.activity` + blocker `activity` (record key `activity`), so a
  lesson can require its subject activity; existing scenarios are unchanged.
- Report note for fact-only records now says "copied from the data library or an automatic check
  of the app" (true for the chemistry balance check and the biology answer check).
