# AI compatibility matrix

Which AI paths of SimLab work, how we know, and what a live check still needs. Written for step
W2 (2026-10-15), from the code and the tests in this repository.

**Read this first.** No row here was checked against a real provider or a real runtime. The agent
that wrote the code and this page never called a real API (Gemini, Claude, Groq) and never started
a local runtime (Ollama, LM Studio, llama.cpp): every test uses fakes — mock HTTP servers in Rust
(`src-tauri/src/ai/mock_server.rs`), mocked `fetch`/`invoke` in unit tests and Playwright routes in
end-to-end tests. The repository has no record of a live run with the user's keys
(`docs/PROGRESS.md`). A fake follows the provider's documentation; a wrong field name in that
documentation would pass every test here and still fail live.

Each row has exactly one status:

| Status                                     | Meaning                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **tested & working (unit/E2E with mocks)** | The whole path runs in automated tests against fakes and passes.                            |
| **implemented, not verified live**         | The code exists; parts are unit-tested, but the path as a whole is not run end to end here. |
| **limited**                                | Works with a stated restriction.                                                            |
| **unsupported**                            | Not available on that path (by design or not built).                                        |

“Desktop” is the Tauri app (every cloud call goes through Rust; keys stay in the OS keychain).
“Browser” is `npm run dev` / the end-to-end tests (`FetchTransport`, keys in session memory or
injected by tests); learners use the desktop app.

## How to run a live check (the user, with their own keys and runtimes)

The agent may not do this. Record each result in `docs/PROGRESS.md` (date, provider or runtime,
model, what was done, what was seen) before changing a row here.

1. Desktop app, Settings → Kết nối AI: “Kiểm tra key” for each provider with its default model.
2. AI Teacher: one question (it should appear while it is written), one board lesson, “Dừng”
   during a long answer, “Viết tiếp” on a cut answer.
3. Think: Gemini draft + Groq review, then Gemma draft + one review provider.
4. “Phân tích đề” on one problem; one spoken answer with the Gemini voice.
5. Each installed runtime: Settings → AI trên máy khác → “Tìm trên máy này”, “Kiểm tra trả lời”,
   one AI Teacher question; one photo with a vision model.
6. Any raw text (status codes, JSON) seen by the learner, or a provider that answers differently
   from its documentation, is a bug to report with the exact screen text (never the key).
